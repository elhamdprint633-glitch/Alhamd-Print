# الحمد برنت 4.0.2 — إصلاح النسخ الاحتياطي والاسترجاع

تاريخ التحديث: 7 نوفمبر 2026، بتوقيت القاهرة.

## سبب المشكلة والإصلاح

الخطأ المبلّغ عنه كان `Error: prompt() is not supported` عند استدعاء زر الاسترجاع. السبب أن Electron لا يدعم نافذة الإدخال `prompt()` المستخدمة في الإصدار السابق. لم يكن امتداد state.alhbak بحد ذاته سبب هذا الخطأ؛ فهو ملف نسخة مشفرة يفتحه البرنامج.

تم استبدال نوافذ الإدخال غير المدعومة بنوافذ داخل التطبيق، وإلغاء حقل اختيار JSON الأول الذي كان يسبق نافذة اختيار أصلية أخرى. أصبح الاسترجاع يستخدم نافذة اختيار واحدة تقبل ZIP وALHBAK وJSON. استُبدل استخدام prompt في إصدار مفتاح طوارئ المدير أيضًا.

أُزيل تبويب «فحص النسخ الاحتياطي» المكرر من «التشغيل والتطوير». كل أدوات الحفظ والفحص والاسترجاع في «الإعدادات > النسخ الاحتياطي». ظل سجل المراجعة محفوظًا، وأصبح في تبويب مستقل باسم «سجل المراجعة».

## الحفظ الجديد

1. سجّل الدخول بحساب المدير، وافتح «الإعدادات > النسخ الاحتياطي».
2. اضغط «حفظ نسخة ZIP كاملة بكلمة مرور».
3. اختر كلمة مرور من 12 إلى 200 رمز وأكدها. هذه كلمة مرور النسخة، وهي مستقلة عن PIN دخول البرنامج.
4. اختر اسم الملف ومكان حفظه في نافذة Windows.
5. سيُحفظ ملف واحد باسم يبدأ بـAlhamd-Backup وينتهي بـ.zip، ويشمل البيانات والمرفقات وأصول المستخدم مثل الخطوط والصور. المحتوى المالي داخل ZIP يظل مشفرًا.
6. احفظ الملف وكلمة مروره خارج الكمبيوتر، واختبر فحصه واسترجاعه على نسخة اختبار. كلمة المرور مطلوبة بعد تصفير البرنامج أو تغيير الجهاز؛ لا توجد استعادة خفية دونها.

لا تفك ضغط ZIP للاسترجاع. مجرد تغيير امتداد ملف قديم إلى ZIP أو JSON لا يحوله إلى الصيغة الجديدة.

## الاسترجاع والفحص

- من نفس قسم الإعدادات، اضغط «اختيار ملف واسترجاع البيانات».
- أدخل كلمة مرور النسخة إذا كانت ZIP جديدة أو نسخة محمولة قديمة. اتركها فارغة للنسخة المحلية القديمة ALHBAK أو JSON.
- أكّد PIN المدير، ثم اختر ملف النسخة نفسه.
- يُفحص الملف قبل استبدال البيانات، وتُحفظ نسخة أمان من الحالة الحالية. إذا كان مرفق حالي ناقصًا، تُحفظ البيانات والمرفقات المتاحة مع بيان النقص؛ فلا يمنع نقص مرفق حالي استرجاع نسخة سليمة.
- يُعاد فتح الواجهة بعد النجاح، وتسجّل الدخول بحسابات وPIN النسخة المسترجعة. الاسترجاع يستبدل البيانات ولا يدمج قاعدتين.
- زر «فحص نسخة ZIP أو ALHBAK أو JSON» يفحص البيانات والمرفقات والأصول دون تغيير البيانات الفعلية.

## النسخ القديمة والتصفير السابق

امتداد .alhbak صيغة مدعومة مشفرة، وليس ملفًا مطلوبًا فتحه من مستكشف Windows. إذا كان state.alhbak ضمن مجلد نسخة قديمة كاملة، احتفظ بالمجلد كله وبمجلدي attachments وUserAssets المصاحبين له.

النسخة المحلية القديمة مرتبطة بمفتاح بيانات الجهاز. بعد إعادة تسمية مجلد البيانات أو تصفير البرنامج قد يتولد مفتاح جديد، حتى على نفس الكمبيوتر ونفس حساب Windows. الإصلاح لا يلغي التشفير ولا يستخرج مفتاحًا مفقودًا. احتفظ بمجلد .old الأصلي كاملًا ومفتاح database-key.dpapi، ولا تحذفه أو تستبدل مفتاح قاعدة البيانات الجديدة منفردًا. قد نحتاج المجلد القديم لاستعادة نسخة محلية أُنشئت قبل التصفير.

أما ZIP الجديدة المحمية بكلمة مرور فتم اختبار استرجاعها بعد استبدال مفتاح الجهاز. ملفات JSON القديمة المتوافقة تبقى مدعومة، بما فيها BOM وصيغ التغليف state/data، دون تغيير القيم المالية أو إنشاء أرصدة أو معرفات عشوائية.

## إصلاحات إضافية في نفس المسار

- تضمين مرفقات التنبيهات، وتفادي تكرار نفس الملف إذا ارتبط بفاتورة وتنبيه.
- عدم معاملة الصورة المدمجة داخل البيانات كملف خارجي مفقود.
- كشف تلف أصول المستخدم حتى في نسخة ZIP خالية من مرفقات الفواتير.
- فك تشفير كل الملفات المطلوبة قبل تعديل الملفات الفعلية، والرجوع عن التعديلات عند فشل الحفظ.
- منع المسارات غير الآمنة داخل ZIP وتحديد الحجم بعد فك الضغط بـ512 ميبيبايت، مع فك الملفات كتدفق محدود الحجم.
- عدم الإبلاغ عن نجاح الحفظ عند إلغاء النافذة أو فشل الكتابة، وتنظيف الملفات المؤقتة.
- سجل الحفظ التلقائي يعرض اسم ALHBAK المحفوظ فعلًا؛ لا يعرض اسم JSON قديمًا.
- فشل النسخة اليومية بسبب عدم إتاحة مجلد النسخ لا يمنع فتح البرنامج؛ تظهر ملاحظة في إعدادات النسخ لمعالجة المجلد.
- الحفظ التلقائي المحلي ما زال ALHBAK للبيانات ومرتبطًا بمفتاح الجهاز، ولا يغني عن ZIP كاملة محفوظة خارج الجهاز.

## التحقق وحدوده

- 180 اختبارًا ناجحًا، دون فشل أو تخطي، وتشمل الاختبارات المحاسبية السابقة.
- اختبارات جديدة للحفظ في ZIP، والتحقق والاسترجاع بعد تغيير المفتاح، وكلمة المرور الخاطئة، وتلف الأصول، والمرفقات المدمجة والتنبيهات، وإلغاء الحفظ وفشل وجهة الكتابة، والنسخ القديمة ومسارات ZIP وأحجامه.
- اختبار Electron فعلي على Linux عبر الواجهة الأصلية: حفظ ZIP، تأكيد كلمة المرور، الفحص، كلمة مرور خاطئة دون شاشة تشخيص قاتلة، تأكيد PIN المدير، الاسترجاع وإعادة تحميل واجهة مقفلة. عادت الفاتورة من200 إلى100، وظل رصيد العميل100 وعاد المرفقان، دون أخطاء JavaScript في الواجهة.
- اختبار إعادة تشغيل مستقل بعد الاسترجاع مع وجهة نسخ غير صالحة: نجح فتح البرنامج والدخول، وظهرت ملاحظة تعذر النسخ.
- استُخدم بديل لمخزن مفاتيح Windows داخل برنامج الاختبار المعزول فقط؛ ليس جزءًا من التطبيق المثبت ولا يثبت عمل DPAPI على Windows.
- لم تُجرَ تجربة المُثبت على Windows فعلي في هذه البيئة. المُثبت غير موقّع بشهادة ناشر تجارية. اختبر التحديث والحفظ والاسترجاع والطباعة على بيانات اختبار قبل اعتماده في التشغيل الحي.
- تظل حدود المراجعة المحاسبية السابقة قائمة: لا يوجد دفتر أستاذ مزدوج القيد أو اعتماد ضريبي تلقائي أو نظام فواتير إلكترونية رسمي. راجع تقرير4.0.1 المحفوظ داخل المصدر للحدود المحاسبية السابقة.
- الاسترجاع يملك رجوعًا عن الأخطاء التي يلتقطها البرنامج؛ لا توجد معاملة ذرية واحدة تشمل SQLite وكل ملفات المرفقات في حالة انقطاع الكهرباء فجأة.

## التثبيت والبناء

أغلق البرنامج وثبّت setup.exe الجديد فوق الإصدار السابق بالطريقة التقليدية Next → Next → Install → Finish. هذا التحديث لا يصفّر حساباتك أو بياناتك. ملف واحد يدعم Windows x64 وARM64. لا تحتاج Node.js لتشغيل النسخة المثبتة.

لبناء المصدر: npm ci ثم npm test ثم npm run dist. المخرج داخل dist-v4.0.2. اختبارات الواجهة المعزولة موضحة في tests/native-402/README.md. المستندات القديمة داخل المصدر مواد تاريخية؛ التعليمات الحالية في README_4.0.2_AR.md ودليل المستخدم المحدث.
