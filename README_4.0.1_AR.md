## نتيجة العمل

تم تعديل المصدر وبناء مُثبت NSIS حقيقي يعمل بنظام المعالج التقليدي: Next → Next → Install → Finish. يشمل ملف واحد معمارية Windows x64 وARM64، ولا يتطلب تثبيت Node.js أو تنزيل مكونات التطبيق عند التثبيت. حجم المُثبت نحو 229.31 ميبيبايت، لأنه يحتوي على محرك Electron لكلا المعماريتين. هذه نسخة 4.0.1 مُرشحة لاختبار القبول؛ لم تُجرَ تجربة تثبيت على جهاز Windows فعلي في هذه الجلسة، ولا يصح وصفها بأنها معتمدة تجاريًا أو ضريبيًا لمجرد نجاح اختبارات المصدر والبناء.

## الاختبارات المنفذة بالفعل

- الاختبارات الموجودة قبل التعديل: 154 ناجحة.
- الاختبارات النهائية بعد إضافة حالات للمشكلات المكتشفة: 172 ناجحة، صفر فشل، صفر تخطي.
- تشمل الاختبارات حفظ وإعادة فتح 30,000 فاتورة، معاملات SQLite، منع الحفظ غير الصحيح، التشفير، النسخ الاحتياطي بالمرفقات واستعادته والتحقق من العبث، تسوية التحصيلات وعدم احتساب العربون مرتين، والصلاحيات.
- اختبار تشغيل Electron فعلي على Linux في وضع headless مع عزل بيانات الاختبار: دخول، إضافة عميل ومورد وخامة، شراء، بيع، تحصيل لاحق، دفعتا خدمة في يومين، حفظ عبر IPC، وتصدير فاتورة PDF فعلية من صفحة واحدة. لم تظهر أخطاء JavaScript في الواجهة خلال السيناريو النهائي.
- اختبار فتح نفس البيانات من عملية جديدة والتحقق من القفل والدخول والرصيد والمستندات وسندات الخدمة.
- السيناريو المالي: افتتاح مخزون10×10؛ وارد10×20 بمدفوع100؛ المتوسط15. بيع وحدتين بسعر25 وعربون20 ثم تحصيل10؛ المتبقي20. خدمة بقيمة100 ودفعتين30 و20؛ رصيد العميل النهائي70، المورد100، كمية المخزون18، وصافي الخزينة-20. الرصيد النقدي السالب هنا ناتج عن عدم إدخال تمويل افتتاحي في السيناريو ولا يُعامل كربح.
- npm audit لكامل الاعتماديات: صفر ثغرات معروفة في وقت الفحص؛ هذه نتيجة قاعدة بيانات التنبيهات وليست إثبات غياب كل ثغرة.
- فحص المُثبت: CRC ناجح، الحجم240454038 بايت. تم التحقق من معمارية الملفين التنفيذيين ومطابقة ملفات المصدر الرئيسية داخل app.asar مع المصدر النهائي، وتفعيل Electron fuses المحددة بالمشروع.
- لم يتم تشغيل مُثبت Windows أو اختبار DPAPI أو Windows Defender/SmartScreen أو الطابعات الفعلية على Windows. لم تُختبر استجابة واجهة المستخدم على أجهزة ضعيفة أو بيانات تشغيل فعلية؛ نجاح اختبار30,000 سجل يخص التخزين وليس ضمانًا لسرعة كل الشاشات.

## حدود محاسبية وتجارية يجب معرفتها

هذا البرنامج لإدارة تشغيل مطبعة وحسابات الأطراف والمخزون والخزينة. لا يحتوي على دفتر أستاذ مزدوج القيد أو دليل حسابات أو ميزان مراجعة قانوني أو إقفال فترات وسنوات مالية أو احتساب واعتماد ضريبة وفاتورة إلكترونية رسمية. تغيير عنوان الطباعة إلى «فاتورة ضريبية» لا ينشئ هذه الوظائف. لا تتضمن هذه المراجعة اعتماد الأرصدة الحقيقية أو صحة التكلفة التاريخية للبيانات القديمة التي لم تُرفق.

سجل التعديلات المحلي أقوى من السابق، لكنه ليس سجلًا رقابيًا موقعًا خارج الجهاز ولا يقاوم كل من يملك صلاحية ملفات النظام. الاسترجاع يملك رجوعًا عند الأخطاء التي يلتقطها البرنامج؛ لا يوجد التزام ذري واحد يجمع SQLite وكل ملفات المرفقات في حالة انقطاع الكهرباء في منتصف الاسترجاع. احتفظ بالنسخة السابقة الكاملة حتى التحقق من النسخة المسترجعة.

لا تُنفّذ هذه النسخة نظام مرتجعات وإشعارات خصم وإضافة عامًا أو مسار رد دفعات خدمات متكاملًا. رفض إنقاص دفعة خدمة يمنع إعادة كتابة تاريخ الخزينة، ويحتاج رد المبالغ إلى إجراء محاسبي معتمد، وليس حيلة بحذف مستند قديم. البيانات القديمة غير المتطابقة قد تُرفض عند الحفظ؛ لا يعاد تصحيحها أو تعديل أرصدتها تلقائيًا، حتى لا يُطمس الخطأ.

## التثبيت وأول تشغيل

1. خذ نسخة كاملة قابلة للاسترجاع من الإصدار المستخدم حاليًا قبل الترقية، واحتفظ بمجلد بياناته الأصلي.
2. شغّل setup.exe على جهاز Windows10/11 بمعمارية64بت. اتبع Next ثم اختيار المجلد ثم Install ثم Finish. المثبت يطلب صلاحية تثبيت على مستوى الجهاز وينشئ اختصار سطح المكتب وقائمة ابدأ.
3. الملف غير موقّع بشهادة ناشر تجارية؛ قد يعرض Windows تحذير ناشر غير معروف. تحقق من بصمة SHA-256 قبل تشغيل الملف.
4. على قاعدة جديدة، حساب المدير الافتراضي «المدير» وPIN هو1234. غيّره مباشرة إلى رقم خاص من4–8 أرقام، وأنشئ مستخدمًا منفصلًا لكل موظف. عند الترقية احتفظ بحساباتك الموجودة.
5. أنشئ مفتاح استعادة المدير واحفظه خارج الجهاز. استخدم نسخة كاملة محمولة بكلمة مرور مستقلة للنقل لجهاز آخر؛ نسخ الجهاز مشفرة بمفتاح مرتبط بحساب Windows ولا تكفي وحدها للنقل أو فقد الجهاز.
6. اختر مجلد نسخ احتياطي مناسبًا، واحتفظ بنسخة خارج الكمبيوتر، وجرّب الاسترجاع في بيئة اختبار. لا تحذف database-key.dpapi أو مجلد البيانات.
7. أدخل الأرصدة الافتتاحية للعميل والمورد والمخزون والخزينة مرة واحدة بعد مطابقتها، دون تكرار الفواتير القديمة التي تمثل نفس الرصيد.
8. اختبر عمليًا على Windows: التثبيت، الإغلاق وإعادة التشغيل، فاتورة نقدية وآجلة، خصومات وبنود متعددة، شراء متعدد الأصناف، دفعات جزئية، هالك وجرد، مستخدم محدود الصلاحيات، PDF والطابعة، ونسخ كاملة بالمرفقات ثم استرجاعها. طابق نتائج كل حالة مع حساب يدوي.
9. قبل البيع أو التعميم، يعتمد محاسب مسؤول سياسة المعالجة والضرائب والأرصدة، وتُستكمل اختبارات قبول Windows. يمكن الرجوع للإصدار السابق من نسخة كاملة محفوظة؛ لا تختبر الرجوع على ملف البيانات الوحيد.

## إعادة البناء من المصدر
