# الحمد برنت 6.2.0 — الكمبيوتر والموبايل

## التحديث

احفظ نسخة احتياطية وأغلق برنامج الكمبيوتر، ثم ثبّت setup.exe فوق النسخة الموجودة: Next → Next → Install → Finish. معرّف التطبيق ومسار البيانات كما هما، دون تصفير حسابات أو حذف بيانات. يدعم Windows 10/11 بنظامي x64 وARM64.

ثبّت Alhamd-Print-Viewer-6.2.0.apk فوق تطبيق الموبايل الموجود، دون إلغاء تثبيته أو مسح بياناته. إصدار الكمبيوتر والموبايل الآن 6.2.0. ارتفع رقم بناء Android إلى 60200، مع بقاء اسم الحزمة eg.alhamd.print.viewer ومفتاح التوقيع السابقين لدعم التحديث من 2.2.0. تظل إعدادات الربط والشعار والأعمدة محفوظة.

## كشف الحساب الحالي ومراجعة الماضي

عند فتح كشف العميل أو المورد، يكون «الحساب الحالي» هو الافتراضي: الحركات التي تلي آخر نقطة وصل فيها صافي الحساب كله إلى صفر. لا يعيد عرض الفواتير المسددة قبلها، ولا رصيد البداية الذي تمت تسويته. إذا لم يحدث تصفير فعلي يبقى الرصيد المستحق محفوظًا.

عند اختيار «هذا الشهر» أو «هذه السنة» يعرض الكشف تاريخ الحساب الكامل داخل الفترة المختارة، بما فيه الفواتير والدفعات القديمة المسددة، حتى لو انتهت الفترة برصيد صفر. يحسب رصيد بداية الفترة من كل الحركات السابقة لبدايتها، وليس من آخر تصفير. الشهر والسنة يمتدان إلى تاريخ اليوم.

لمراجعة شهر أو سنة سابقة، اختر تاريخ البداية والنهاية واضغط تطبيق على الكمبيوتر، أو «فترة محددة» على الموبايل. مثلًا: 2026-01-01 إلى 2026-01-31. يعيد زر «الحساب الحالي» العرض الافتراضي بعد آخر تصفير. اختيار الفترة لا يسجل تسوية جديدة ولا يغير أي فاتورة أو دفعة.

مثال: رصيد سابق 100 + فاتورة قديمة 50 − سداد 150 = صفر، ثم فاتورة جديدة 30. «الحساب الحالي» يعرض الفاتورة الجديدة ورصيد 30. اختيار شهر الفاتورة القديمة يعرض رصيد البداية 100 والفاتورة 50 والسداد 150 ورصيد نهاية الفترة صفرًا. الصفر هنا يخص الفترة التي تراجعها، ولا يعني أن رصيد الحساب الحالي 30 قد اختفى.

تنطبق القاعدة على العملاء والموردين والحساب الموحد للجهة المسجلة عميلًا وموردًا، مع اتجاه الرصيد الصحيح. لا يتم توزيع دفعات جديد أو حذف أي سجل؛ الحسابات والمخزون والخزينة محفوظة. يظل البحث والفلتر الإضافي داخل الجدول فعالًا على النتائج؛ امسح أي فلتر إضافي إذا أردت رؤية كل الحركات في الفترة.

معاينة وتصدير كشف الحساب على الكمبيوتر يستخدمان الفترة المعروضة نفسها. عند تغيير الفترة، تأكد من العنوان «رصيد نهاية الفترة المختارة» بدل اعتباره رصيد اليوم.

## واجهة المستندات على الموبايل

عرض فاتورة العميل أصبح منظمًا: شعار وهوية المطبعة بالألوان، رقم الفاتورة والتاريخ، العميل والتسليم والمواصفات، ثم جدول البنود وملخص واحد للصافي والخصم والمسدد والمتبقي. تبقى أعمدة الفاتورة قابلة للإظهار والإخفاء من الإعدادات. أمر التشغيل يحتفظ بإخفاء أعمدة الأسعار.

كشف العميل والمورد يظهران في مساحة الشاشة، مع اختيارات «الحساب الحالي / هذا الشهر / هذه السنة / فترة محددة»، ورصيد نهائي كبير واضح واتجاهه. الجدول يعرض التاريخ والبيان والمستحقات والسداد والرصيد المتحرك. تُعرض الحركات كل 100 حركة مع بقاء الإجماليات شاملة لكل حركات الفترة. اسحب الجدول أفقيًا لمراجعة الأعمدة الواسعة دون تصغير الكتابة لدرجة غير مقروءة.

تظهر رصيد بداية الفترة الحقيقي عند وجوده، وتختفي خانة البداية الصفرية في الحساب الحالي. الحساب المصفر بالكامل يكتب «الحساب خالص»، بينما الفترة التاريخية تظل تعرض فواتيرها المسددة وحركات سدادها.

المصادر والسجلات المرتبطة موجودة في قسم قابل للفتح أسفل المستند؛ اختيار فاتورة للمشاركة من كشف الحساب مستمر. الموبايل للعرض والمشاركة فقط.

## المعاينة والمشاركة

زر «معاينة PDF» يجهز مستندًا ويعرض ملف PDF نفسه، صفحة بصفحة، مع التكبير بإصبعين أو الأزرار والتنقل بين الصفحات. يمكن مشاركة ملف PDF نفسه من داخل المعاينة. المعاينة صورة ثابتة من بيانات اللحظة التي جهزتها؛ إذا وصلت معاملات جديدة أغلقها وأعد فتحها لرؤية المستند الأحدث.

زر «مشاركة كشف الحساب» يستخدم الفترة المختارة نفسها، بصيغة PDF أو PNG. تصدير الكشف أصبح جدولًا واضحًا مع ملخص واحد في نهايته. الفاتورة والكشف يشتركان في ألوان وهوية المستند وشعار المطبعة والعلامة المائية. تبقى إعدادات شعار الهاتف والعلامة المائية المحلية كما كانت.

PDF أنسب للمستندات الطويلة ويحافظ على وضوح النصوص عند التكبير. PNG متاح حتى ست صفحات؛ إذا زاد الكشف عن ذلك استخدم PDF أو فترة أقصر. المعاينة تحمل صفحة واحدة في كل مرة لتقليل استهلاك الذاكرة. لا تُضاف أي فاتورة أو حركة مالية من المعاينة أو المشاركة.

## الربط والميزات السابقة

الربط المحلي وربط Tailscale المحفوظان مستمران. إغلاق التطبيق والبرنامج لا يلغي الاعتماد؛ عند فتحهما تعود المحاولة تلقائيًا. للوصول من خارج المطبعة يجب بقاء الكمبيوتر مستيقظًا والبرنامج مفتوحًا وTailscale متصلًا على الطرفين. إلغاء الاعتماد يدويًا أو مسح بيانات التطبيق يتطلبان اعتمادًا جديدًا.

تستمر فاتورة الكمبيوتر بملء الشاشة، والرصيد الإرشادي قبل الحفظ، وفتح المصدر الدقيق مع تمييزه، وإعدادات الفاتورة الأساسية. لا يعود مصمم الفاتورة الملغى، ولا توجد إضافة واتساب مدمج في هذا التحديث.

## التحقق وحدوده

نجح 257 اختبار Node للحسابات والمخزون والصلاحيات والنسخ الاحتياطي والربط، بما فيها مراجعة فواتير مسددة داخل فترة تاريخية مع صحة رصيد بدايتها ونهايتها. نجحت اختبارات واجهة الكمبيوتر للحالي والشهر والسنة والفترة المخصصة والعودة للحالي، وتجربة Electron وSQLite وIPC وتصدير كشف تاريخي دون تغيير السجلات المالية.

تطابقت نتائج Java للموبايل مع الكمبيوتر في 30 حالة من الحساب الحالي والفترات التاريخية والمقاصة. نجح اختبار عميل Java الحقيقي لإعادة الاتصال بعد إعادة إنشاء الخدمة بنفس الاعتماد وبصمة الشهادة.

نجحت ثلاثة اختبارات Android عبر Robolectric بالرسم الأصلي: فتح كشف الحساب والتبديل بين الحالي والفترة، ورسم فاتورة وكشف تاريخي، وتقسيم كشف طويل دون فقد المعاملات. توجد صور الناتج ضمن حزمة التحقق. هذه محاكاة وليست تشغيلًا على هاتف فعلي. لا يدعم هذا المحاكي تنفيذ PdfDocument/PdfRenderer الأصليين بالكامل؛ لذلك اختُبر رسم الصفحات وملف PNG المشترك مع مسار PDF، ولم يُنفّذ حفظ PDF أو شاشة تكبير PDF فعليًا على Android. APK اجتاز البناء والتحقق من التوقيع بالمفتاح السابق.

اجتاز مثبت Windows فحص CRC، وطابقت ملفات التطبيق في حمولتي x64 وARM64 المصدر المختبر. لم يُشغّل المثبت على Windows فعلي، ولم تُختبر شبكة Tailscale الخاصة بالمستخدم أو Windows DPAPI داخل هذه البيئة؛ استخدمت تجربة مفاتيح Linux بديلًا للاختبار فقط. مثبت Windows غير موقع بشهادة ناشر تجارية. الاختبارات لا تضمن غياب كل عيب على كل جهاز أو بيانات.
