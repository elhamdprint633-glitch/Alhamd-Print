# الحمد برنت — الكمبيوتر 6.0.0

## التثبيت كتحديث

احفظ نسخة احتياطية، ثم أغلق البرنامج وثبّت setup.exe فوق النسخة الحالية: Next → Next → Install → Finish. احتُفظ بمعرّف التطبيق eg.alhamd.print.desktop واسم الملف التنفيذي ومسار البيانات وإعداد عدم حذف بيانات التطبيق. لا تحذف بياناتك ولا تصفّر الحسابات. المُثبت يشمل Windows x64 وARM64. رقم الإصدار 6.0.0، وليس 2027.

تطبيق الموبايل 2.1.0 السابق مستمر كما هو، ويمكن تنزيل نفس APK عند الحاجة. لا تحتاج إزالة التطبيق أو إعادة اعتماده بسبب رقم إصدار الكمبيوتر وحده؛ بيانات الهوية والبصمة واعتماد الهواتف محفوظة. لم يتغير بروتوكول العرض.

## التعديلات المطلوبة فقط

حُذف قسم مصمم الفاتورة ومسار تحميله واستيراد PNG/PSD الخاص به ومحرك قوالبه. تُستخدم الفواتير الأساسية للبرنامج وإعداداتها العادية، بما فيها الأعمدة وترتيبها والإظهار والإخفاء والألوان/الأبيض والأسود والملء. القوالب القديمة لا تُفعّل حتى إن كانت محفوظة ضمن بيانات إصدار سابق؛ لا تُحذف المعاملات ولا يعاد حسابها. إعدادات الفاتورة الأصلية الأخرى محفوظة.

لم تُضف مقترحات أعمار المديونيات أو الحدود الائتمانية أو قفل الفترات أو التقارير الجديدة. الربط المحلي وTailscale مستمران. واتساب المدمج ما زال مؤجلًا.

## الرصيد الإرشادي في شاشة الفاتورة

تحت اختيار العميل يظهر حقل واحد مقسوم: في اليمين «الرصيد السابق»، وفي اليسار «الإجمالي المتوقع» بعد الفاتورة الحالية. يتحدث أثناء تعديل الكميات والأسعار وخصومات البنود والفاتورة والمدفوع، دون الضغط على حفظ.

**الإجمالي المتوقع = الرصيد السابق + صافي الفاتورة بعد الخصم − المدفوع الحالي.**

مثال: سابق 470، صافي فاتورة 300، إجمالي 770. كتابة مدفوع 200 تجعل المتوقع 570. لو كان الرصيد دائنًا للعميل، تُطرح قيمته من المستحق، ويتغير الوصف بين «عليه لنا» و«له عندنا» وفق النتيجة، وعند الصفر يظهر «الحساب خالص».

الحساب الموحد للجهة المسجلة عميلًا وموردًا يستخدم المقاصة الموجودة مرة واحدة. لا تُخصم أرصدة المورد مرتين. للمورد في وارد الخامات والمسحوبات يظهر الرصيد وفق اتجاه حساب المورد: الموجب «له عندنا»، والسالب «عليه لنا»، مع الإجمالي المتوقع بعد صافي المشتريات والمدفوع.

في تعديل مستند محفوظ، يظهر الحالي قبل التعديل يمينًا والمتوقع بعد التعديل يسارًا؛ يُستبدل أثر المستند الأصلي بدل جمع قيمته مرتين، وتظل الدفعات اللاحقة محسوبة في رصيد الحساب.

**هذه أرقام معاينة فقط.** الكتابة في الحقول لا تسجل فاتورة أو سندًا أو حركة خزينة أو مخزون. تسجيل المعاملة يحدث من زر الحفظ وفق التحقق المحاسبي الحالي. الحقل لا يسجل تحصيل مديونيات قديمة تلقائيًا ولا يغيّر قواعد السماح بالمدفوع في الفاتورة؛ تحصيل حساب قديم يستمر من سند التحصيل/الخزينة كما كان. لا يظهر حقل رصيد للعميل النقدي، وتختفي الأرقام في الوضع الخاص وعند القفل.

## العلامة المائية

من إعدادات الفاتورة اختر بدون أو نص أو شعار المطبعة أو صورة أخرى. الزاوية والحجم والشفافية تعمل على الصورة والنص، واللون يعمل على العلامة النصية. تغيير الزاوية إلى صفر يطبق فعلًا، ولا تبقى زاوية القالب السابق مفروضة.

تظهر العلامة فوق محتوى الفاتورة والجداول والتعبئات داخل حدود المستند، مع إبقاء الشفافية قابلة للتعديل للمحافظة على وضوح النص. تمت إزالة اختيار إعادتها خلف الجداول تلبية للطلب. العلامة الكبيرة تُقص داخل حدود الورقة حتى لا توسّع الصورة المصدرة أو تقص بيانات الجانب الأيمن.

تطبق الإعدادات نفسها على الفاتورة وكشف الحساب والمستندات المتصلة بمحرك الفواتير، في المعاينة وPDF والصور. الصور المنسوخة تظل بدقة 300 DPI، وكشف الحساب يحتفظ بجدول واضح وملخص مالي واحد في نهاية المستند.

## الربط المحلي أو أونلاين

الربط المحلي: الكمبيوتر والهاتف على نفس الشبكة الخاصة الموثوقة، IP الكمبيوتر ومنفذ 47821 ورمز الربط المحلي. لا تفتح 47821 للإنترنت.

أونلاين: ثبّت Tailscale على الكمبيوتر والهاتف وسجلهما في نفس الحساب أو شبكة Tailscale الخاصة، وشغّل الاتصال. من «ربط الموبايل ← إعداد الربط باستخدام Tailscale» على الكمبيوتر، اضغط تحديث الحالة ثم تشغيل الربط. على الهاتف اختر «عبر Tailscale HTTPS» وأدخل العنوان والبصمة ورمز الاعتماد من شاشة الكمبيوتر.

لا يحتاج Tailscale إلى IP عام أو تحويل منفذ الراوتر. قد يلزم السماح بمنفذ TCP 47822 في جدار حماية الكمبيوتر وسياسات شبكة Tailscale للأجهزة الموثوقة. لا يغير البرنامج الجدار أو السياسات تلقائيًا. Tailscale ينسّق الاتصال وقد يمرر اتصالًا مشفرًا، ولا يستضيف برنامج الحسابات أو قاعدة بياناته.

يبقى الكمبيوتر مستيقظًا والبرنامج مفتوحًا للوصول للبيانات الحديثة. بعد حفظ المسارين لنفس الكمبيوتر، يفضل الهاتف المحلي المشفر ثم Tailscale عند تعذره. لا يرجع تلقائيًا إلى إرسال اعتماد HTTPS عبر HTTP. بدون اتصال يعرض آخر نسخة محفوظة مع وقتها، والهاتف للعرض والمشاركة فقط دون تسجيل معاملات. إلغاء اعتماد الهواتف يسحب صلاحية الوصول كما في الإصدار السابق.

## الاختبارات وحدودها

نجح 249 اختبارًا آليًا تشمل الحسابات والمخزون والصلاحيات والنسخ الاحتياطي والمقاصة والخصومات والربط المشفر، والمعاينة الجديدة والعلامة المائية والتحديث. أزيلت الاختبارات الخاصة بالمصمم الملغى وأضيفت الاختبارات المناسبة للسلوك الحالي.

نجح اختبار واجهة فعلية للتحديث أثناء كتابة المدفوع والخصم، وترتيب جانبي الحقل، وإخفاء الأرصدة في الوضع الخاص والعميل النقدي، واستبدال أثر الفاتورة عند التعديل، وتحديث المورد في المشتريات والمسحوبات، وعدم تعديل المعاملات أثناء المعاينة.

نجحت تجربة البرنامج الفعلي عبر Electron وSQLite وIPC: لم تضف المعاينة مستندًا أو حركة مالية إلى قاعدة البيانات؛ نجح تصدير الفاتورة والكشف ونسخ الصورة. اختلفت صورة PDF عند تغيير زاوية العلامة من 0° إلى 45° مع ثبات مقاس الصفحة، وثبت مقاس صور الحافظة 2479 × 1897 في عينة الاختبار. نجحت شاشة Tailscale دون الاعتماد على مكتبة المصمم المحذوفة. حزمة التحقق تتضمن فحص CRC وحمولتَي Windows ومطابقة ملفات التطبيق للمصدر وعدم وجود المصمم داخل المُثبت.

لم يُشغل المُثبت على Windows فعلي، ولم يُختبر APK على هاتف فعلي أو اتصال طرفين عبر شبكة Tailscale خاصة بالمستخدم في هذه البيئة. اكتشاف Tailscale اختُبر بحالات CLI محاكاة، والتشفير والاعتماد بخدمتي HTTP وHTTPS فعليتين داخل الاختبار. حماية المفاتيح على Linux استخدمت بديلًا للاختبار؛ Windows DPAPI نفسه لم يُختبر هنا. المُثبت غير موقع بشهادة ناشر تجارية. لا تعني الاختبارات ضمان غياب كل عيب على كل جهاز أو قاعدة بيانات.
